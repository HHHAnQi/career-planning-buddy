## 1. 项目背景

### 1.1 用户问题

用户在求职、考公、学习成长等阶段的核心困难不是缺少信息，而是**信息过载、路径不清、计划过重、行动启动困难和焦虑反复**。市面上的产品要么给海量内容让用户自己筛（题库、招聘平台），要么给个空待办让用户自己填（任务管理工具），要么被动问答交给用户自己追问（通用大模型）。

没有一个产品帮用户回答："我现在该先做什么？"

### 1.2 为什么是现在

- **用户侧**：公开信息足够多，但用户缺少筛选、排序并转成今日行动的能力。
- **技术侧**：LLM、联网搜索、RAG 和状态图编排已经能支持诊断、检索、计划、校验的受控流程。
- **产品侧**：单纯聊天和待办工具都难以解决"我知道要努力，但不知道今天先做什么"的问题。

### 1.3 竞品格局与空白

| 赛道 | 代表产品 | 共性缺口 |
|---|---|---|
| 求职辅导 | 超级简历、BOSS 直聘、牛客网 | 集中在简历/刷题/招聘匹配等执行末端，无人做前置规划 |
| 考公备考 | 粉笔、华图、中公 | 重内容/课程/题库，AI 只用于批改；零基础用户"怎么开始"是空白 |
| 任务管理 | 番茄 TODO、滴答清单 | 只管"强制你做"，不管"该做什么" |
| 通用大模型 | 豆包、Kimi、通义、DeepSeek | 能力够但被动问答；无结构化任务输出、无任务状态闭环、无统一记忆管理 |

**三大空白点**：
1. 无人做"诊断→规划→今日小步"的前置链路
2. 无人做"低压力启动"定位
3. 无人做"受控多 Agent + 统一记忆 + 来源核查"的工程化封装

详细竞品分析见 [《可行性分析报告》](./01_可行性分析报告_v1.0.md) 第一章。

## 2. 需求目标

### 2.1 业务目标

验证一个核心假设：**AI 能否把混乱信息收敛成用户今天愿意开始并完成的第一步，并形成"计划→执行→复盘→调整"的闭环。**

### 2.2 衡量指标（OKR 式）

**北极星指标：每周第一步完成率（Weekly First-Step Completion Rate）**

定义：过去 7 天内，至少完成 1 个 starter_action 的用户数 / 7 天内生成过计划的用户数。

为什么是它：
- 比计划采纳率更深一层——采纳只是"点了开始"，第一步完成才是"真的做了"
- 比 7 日回访率更聚焦价值——回访可能是习惯或无聊，第一步完成是核心价值验证
- 同时验证三件事：① 用户信任 AI 计划（不信任不会做）② 计划真的可执行（不可执行做不完）③ 低压力策略有效（策略无效会放弃）

| 类型 | 指标 | 口径 | MVP 目标 |
|---|---|---|---|
| 🔥 **北极星** | **每周第一步完成率** | 过去 7 天内完成 ≥1 个 starter_action 的用户 / 7 天内生成过计划的用户 | **≥ 35%** |
| 业务 | 计划采纳率 | 生成计划后点击开始任一任务的用户占比 | ≥ 50% |
| 业务 | 复盘提交率 | 当天有任务用户中提交复盘的比例 | ≥ 30% |
| 业务 | 7 日回访率 | 首次使用后 7 日内再次打开的用户占比 | ≥ 15%（MVP 无主动推送，属合理范围） |
| 质量 | 计划过重率 | 用户标记"太多/太难/不想做"的计划占比 | ≤ 20% |
| 质量 | 来源可靠率 | 带来源计划中官方/JD/高质量来源占比 | ≥ 70% |
| 技术 | Agent 成功率 | agent_runs 成功完成数 / 总运行数 | ≥ 95% |
| 技术 | 结构化输出通过率 | 符合 schema 的节点输出数 / 节点总输出数 | ≥ 98% |
| 技术 | 受控 Loop 触发率 | 发生校验重写的 run 占比 | ≤ 30% |
| 技术 | 单次运行成本 | 按 run 记录 token、模型成本、端到端耗时 | ≤ ¥0.2 / 次 |
| 技术 | 端到端延迟 | plan_run 从触发到结果返回 | P95 ≤ 20s |

> 7 日回访率从原 ≥35% 下调到 ≥15%——MVP 阶段无主动推送，35% 缺乏产品手段支撑。达到 15% 算合格，靠次日续接卡片 + 回归欢迎语等被动召回机制实现。上线后若加主动推送再上调目标。

### 2.3 用户目标

从"不知道怎么开始"到"今天先完成这一小步"。

### 2.4 技术目标

验证受控 Agent 架构能否稳定控制工具调用、来源标注、状态记录和失败降级。

### 2.5 MVP 成功标准

> 定义"MVP 做完"的判断依据，避免开发完了不知道"做没做出来"。

MVP 阶段需**4 项全部达标**才算成功：

| 维度 | 标准 | 判定方式 |
|---|---|---|
| 质量覆盖 | 3 个首发场景各跑通 10 个评测 case（共 30 case，含正常/异常路径），通过率 ≥ 85% | 固定评测集 |
| 北极星 | 每周第一步完成率 ≥ 35% | 用户行为埋点 |
| 计划质量 | 计划过重率 ≤ 20% | 用户反馈埋点 |
| 安全合规 | 心理危机误判/漏判 = 0，高风险分流全部正确触发 | 安全事件审计 |

判定级别：
- **4 项全达标** = MVP 成功，可进入迭代优化
- **3 项达标** = MVP 基本成功，剩余 1 项进入下一迭代修复
- **≤ 2 项达标** = MVP 未达预期，需根据 Plan B 做重大调整

## 3. 目标用户与画像

### 3.1 用户分层

| 用户层 | 当前行为 | 核心痛点 | 产品响应 |
|---|---|---|---|
| 目标模糊型 | 反复搜索经验帖、岗位要求和备考路线 | 信息多但无法判断先后顺序 | 输出清晰路径和第一步任务 |
| 计划过重型 | 列计划后很快放弃 | 任务颗粒度过大，开始成本高 | 把计划压缩为 1-3 个低压力任务 |
| 执行摇摆型 | 完成几天后中断，复盘少 | 不知道是计划不合适还是状态差 | 记录完成/放弃原因并调整后续难度 |
| 动态信息依赖型 | 需要报名、招聘、岗位变化等最新信息 | 担心信息过期或来源不可靠 | 动态事实联网核查并标注来源 |

### 3.2 典型 Persona

**Persona A：目标模糊型 — 小张**
- 22 岁，计算机本科应届，想进央国企但不知道先补专业课、做项目、改简历还是刷题
- 行为：收藏了几十个经验帖，但没有一条看完并执行
- 期望：告诉我"这周先做项目，今天先花 30 分钟把项目框架搭起来"

**Persona B：计划过重型 — 小李**
- 24 岁，在职备考省考，每天列详细计划但三天后放弃
- 痛点：计划一拆就是 10 个任务，看到列表就不想开始
- 期望：别给我一堆，就给我今天能做完的 1-3 个

**Persona C：执行摇摆型 — 小王**
- 23 岁，准备 AI 后端实习，断断续续学了两周
- 痛点：不知道是计划不合理还是自己状态差，中断后不知道怎么续
- 期望：帮我记一下上次做到哪、为什么停，然后给我今天能接上的任务

### 3.3 MVP 首发场景

产品是**通用 AI 规划陪伴助手**，不限制用户能问什么。但 MVP 阶段经验原子库和测试验证聚焦以下三个首发场景，保证回答质量：

| 首发场景 | 典型用户 | MVP 需解决到什么程度 |
|---|---|---|
| 计算机央国企求职 | 不知道先补专业课、项目、简历还是刷题 | 给出整体方向、本周重点和今日可执行任务 |
| 考公/事业编准备 | 不知道行测、申论、岗位选择和备考节奏如何开始 | 把备考路径拆成阶段计划和低压力启动任务 |
| AI/后端/Agent 应用求职 | 面对岗位要求、项目包装、简历和面试准备感到混乱 | 结合岗位信息和用户基础，生成准备路径和今日任务 |

未支持场景（如学英语、健身、考证）走通用规划模式：诊断 Agent 识别为"通用场景"后，坦诚告知"这是通用建议，部分领域可能不够专业"，但仍然给出基础规划。经验原子库按场景逐步扩展。

### 3.4 用户场景边界

| 场景 | 产品做 | 产品不做 |
|---|---|---|
| 学习/备考/求职路径规划 | ✅ 整体方向 + 本周重点 + 今日任务 | ❌ 不替代专业心理咨询、医疗诊断、法律意见、金融建议 |
| 情绪记录与陪伴 | ✅ 复盘时记录情绪、低压力话术 | ❌ 不做心理治疗、不开药、不 diagnose |
| 动态信息核查 | ✅ 招聘/考试/政策等动态事实联网核查 + 来源标注 | ❌ 不保证信息 100% 准确，以官方公告为准 |

## 4. 用户故事与用户旅程

### 4.1 核心 User Stories

| # | 角色 | 故事 | 验收价值 |
|---|---|---|---|
| US-01 | 目标模糊型用户 | 作为不知道先做什么的求职者，我希望 AI 帮我理清整体方向并给出今天的第一步，这样我不用再纠结该从哪开始 | 计划采纳率 |
| US-02 | 计划过重型用户 | 作为总是列大计划然后放弃的人，我希望每天只收到 1-3 个小任务，这样我不会有启动压力 | 第一步完成率 |
| US-03 | 执行摇摆型用户 | 作为中断后又想继续的人，我希望 AI 记住我上次做到哪、为什么停，这样我能无缝接上 | 7 日回访率 |
| US-04 | 动态信息依赖型用户 | 作为担心信息过期的考公用户，我希望 AI 联网查最新公告并标来源，这样我能放心按计划行动 | 来源可靠率 |
| US-05 | 所有用户 | 作为用户，我希望随时查看 AI 记住了我什么、能删除和关闭，这样我不用担心隐私失控 | 记忆管理可见性 |
| US-06 | 所有用户 | 作为用户，我希望每天能简单复盘一下，这样 AI 能根据我的状态调整后续任务 | 复盘提交率 + 闭环 |

### 4.2 用户旅程图（Happy Path）

```
首次进入
  │
  ├─ 建档：填写目标/阶段/可用时间（必填）+ 可选字段
  │    └─ 缺必填 → Agent 追问 1-3 个关键问题 → 补齐后继续
  │
  ├─ 生成规划
  │    ├─ 诊断 Agent：识别目标、阶段、焦虑点、是否需追问
  │    ├─ 搜索蒸馏 Agent：联网 + 经验库，整理成经验原子
  │    ├─ 计划 Agent：生成整体方向 + 本周重点 + 今日 1-3 任务
  │    └─ 校验陪伴 Agent：检查可执行性、来源、话术低压力
  │         └─ 校验失败 → 回计划 Agent 重写（最多 2 次）→ 仍失败 → 模板降级
  │
  ├─ 今日任务卡
  │    ├─ 点击"开始" → 状态=进行中
  │    ├─ 点击"完成" → 状态=已完成 + 记录时间
  │    └─ 点击"放弃" → 必须选择/填写原因 → 进入复盘
  │
  ├─ 每日复盘
  │    ├─ 提交完成情况、情绪、阻碍、调整建议
  │    ├─ 更新完成率、常见阻碍、任务偏好
  │    └─ 生成记忆候选（敏感记忆需用户确认）
  │
  └─ 次日续上
       ├─ 读取昨日完成情况 + 复盘 + 记忆摘要
       ├─ 根据状态调整今日任务数量/难度
       └─ 循环回到"生成规划"
```

### 4.3 关键分支与异常出口

| 分支 | 触发条件 | 系统行为 |
|---|---|---|
| 信息追问 | 缺少必填字段 | Agent 最多追问 1-3 个关键问题，不生成长计划 |
| 来源不足 | 搜索结果质量低 | 只给方向性建议，不给确定结论，标注"建议自行核实" |
| 校验失败 | 校验节点判定计划不可执行/话术不当 | 回计划 Agent 重写，最多 2 次，仍失败降级模板计划 |
| 高风险触发 | 用户输入涉及心理危机/医疗/法律/金融 | 停止普通规划，返回固定安全提示 + 求助资源，不进入记忆 |
| 联网失败 | 搜索 API 超时/不可用 | 使用经验缓存/基础模板，提示"未完成实时检索" |
| 模型超时 | 单节点 LLM 调用超时 | 降级为模板计划，记录失败到 agent_steps |

### 4.4 流失路径分析

> Happy path 之外的关键流失时刻——用户在什么时候可能走人，对应的产品/设计策略是什么。

| 流失时刻 | 用户内心独白 | 产品策略 |
|---|---|---|
| 建档时（填写摩擦） | "又要我填一堆资料" | 建档精简到 3 必填（目标/阶段/可用时间）；其余字段标注"可以以后再补"，基于后续对话慢慢补全画像 |
| 等待规划时（15-20s 空白） | "怎么这么慢" | 过渡态期间每 3-5s 更新进度提示（"已读取你 3 天前的复盘..." "正在联网核查招聘信息..."），让等待可见化 |
| 看到任务卡（不信任） | "这任务不靠谱 / AI 不懂我" | 来源标注 + "我为什么这么建议"解释卡片 + "调整任务"按钮（一键让 Agent 重生成），降低首次信任门槛 |
| 做完第一天不回来（无激励） | "做完了没什么感觉" | 第一个任务完成时的非泛泛庆祝 + 次日打开直接显示续接卡片（"你昨天 XX 任务还差 Y，今天 5 分钟可以结束掉"） |
| 连续放弃（挫败感累积） | "我果然做不到" | 不评判，主动降到 1 个任务/天 + 共情话术；连续放弃 3 天后触发"要不要换个目标或暂停几天"的允许放弃选项，不给压力 |
| 连续 2 天未打开（隐性流失） | "忘了有这个产品" | 再次打开时显示回归欢迎话术（"X 天没见了，最近怎么样？要不要重新看看方向？"）+ 一键恢复规划 |

## 5. 产品方案概述

### 5.1 一句话定位

一个通用的 AI 规划陪伴助手：通过联网搜索、经验蒸馏、统一记忆和计划校验，把混乱信息转成用户今天可以开始的行动——给出整体规划、今日小任务和低压力陪伴。

### 5.2 质量分层（三圈质量模型）

AI 规划搭子是**真正的通用规划助手**——用户可以问任何目标，系统都会给规划。质量按目标类型分层：

```
┌────────────────────────────────────┐
│ 外圈：任意目标（学吉他、健身、考证）  │  通用规划能力（LLM + 联网）
│  ┌──────────────────────────────┐  │
│  │ 中圈：学习/职业/备考类目标     │  │  + LLM 规划增强
│  │  ┌────────────────────────┐  │  │
│  │  │ 内圈：三首发场景        │  │  │  + 经验原子库加持
│  │  │（央国企求职/考公/AI实习）│  │  │  （质量最高，面试 demo 主打）
│  │  └────────────────────────┘  │  │
│  └──────────────────────────────┘  │
└────────────────────────────────────┘
```

- **内圈（三首发场景）**：央国企求职 / 考公入门 / AI 后端实习。有经验原子库加持，规划质量最高。PRD 文档中以这三场景走通完整示例。
- **中圈（学习/职业/备考类目标）**：如学英语、转行、考研等。依靠 LLM 通用规划能力 + 联网搜索，质量良好。
- **外圈（任意目标）**：如学吉他、健身、旅行规划等。依靠 LLM 通用规划能力 + 用户记忆，坦诚告知"这是通用建议，部分领域可能不够专业"，仍给基础规划。

**三首发场景是设计与测试的举例说明**——本 PRD 文档中以这三场景走通完整示例，但产品本身不限制用户目标类型。经验原子库按场景逐步扩展。

### 5.3 核心差异化

**动态经验规划引擎**：把公开经验、动态信息、用户记忆和执行记录转成整体规划与今日小任务。不是聊天机器人，不是待办工具，而是介于两者之间的"规划生成器 + 低压力陪伴"。

### 5.4 "陪伴"的产品行为定义

"陪伴"由两层共同构成——**记忆驱动个性化**（功能层）+ **关键时刻反馈话术**（表达层）。只靠记忆不够（AI 记住了但沉默，用户感受不到陪伴）；只靠话术不够（AI 嘴上鼓励但不记你，每天要重新解释自己）。

**陪伴落地为 6 个触发时刻**：

| 触发时刻 | 陪伴行为 | 数据来源 |
|---|---|---|
| 用户完成第一个任务 | 非泛泛的庆祝话术（引用具体完成内容，如"你今天完成了项目框架搭建"） | 任务记录 |
| 用户放弃任务 | 非评判式回应（不说"怎么又放弃"），记录原因后温和调整后续 | 放弃原因 |
| 用户连续放弃 N 天 | 放弃说教，主动降到 1 个任务/天，并说"最近辛苦了，今天先做这一个就好" | 任务统计 |
| 复盘记录情绪低落 | 共情但不 diagnose（"听起来这段时间确实很难"），不进入心理干预 | 复盘情绪 |
| 次日续上 | 引用昨日记忆（"你昨天做完 XX 了，今天接 XX 试试"），不是冷冰冰重启 | 记忆摘要 |
| 规划生成等待 | 过渡态期间呈现"正在结合你 X 月 X 日的复盘/偏好生成"等个性化提示 | 记忆摘要 |

**校验陪伴 Agent 输入增补**：除计划/来源/偏好外，**显式输入用户近期记忆摘要和统计**，让 Agent 在话术层体现"它记得你"。

### 5.5 产品架构（产品视角）

系统由四个产品层组成（技术实现见 ADR）：

| 层 | 职责 | 用户可见 |
|---|---|---|
| 交互层 | 前端客户端（MVP 本地 Web 端，远期上线微信小程序）：对话页、今日计划页、任务卡、复盘页、记忆管理页 | ✅ 全部用户可见 |
| 业务层 | 用户/画像/计划/任务/复盘/记忆的 CRUD、权限事务、内容审核 | ❌ 后台可见 |
| Agent 层 | 受控多 Agent 工作流：诊断→搜索蒸馏→计划→校验陪伴 | ❌ 通过结果可见 |
| 知识层 | 统一记忆服务 + 经验原子库 + 联网搜索 | ❌ 通过来源和记忆可见 |

**产品对系统的约束（非技术选型）**：
- 受控：Agent 在受控流程内行动，不做开放式自治
- 可降级：任何节点失败必须有降级路径，不能"卡住"
- 可追踪：每次规划可回溯到诊断/搜索/计划/校验节点
- 来源可信：动态事实必须标注来源，不编造
- 安全边界：高风险内容必须分流，不进入普通规划

### 5.4 核心流程

```
用户消息 → 诊断（识别意图/阶段/缺口） → 是否需追问？
                                              ├─ 是 → 返回追问
                                              └─ 否 → 并行[记忆检索 + 经验检索 + 联网搜索]
                                                         → 搜索蒸馏（整理经验原子）
                                                         → 计划生成（整体方向 + 本周 + 今日任务）
                                                         → 校验陪伴（可执行性 + 来源 + 话术）
                                                              ├─ 通过 → 返回结果
                                                              └─ 失败 → 重写（≤2 次）→ 模板降级
```

### 6.2 首次建档 [P0]

**功能描述**：用户首次进入产品时，采集规划必要信息，建立用户画像。

**业务规则**：
- 必填字段：目标、阶段、可用时间
- 可选字段：基础水平、偏好、当前情绪、已有准备情况、近期节点
- 缺少必填字段时，系统不生成长计划，Agent 最多追问 1-3 个关键问题
- 用户完成最小建档后，系统进入规划流程

**交互流程**：
1. 用户首次进入 → 展示建档引导（字段采集表单或对话式采集）
2. 用户提交 → 系统校验必填字段
3. 缺必填 → Agent 追问关键问题 → 用户回答 → 补齐
4. 信息足够 → 生成用户画像记录 → 进入规划流程

**异常与边界**：
| 场景 | 处理 |
|---|---|
| 用户跳过必填字段 | 进入追问流程，不强制阻塞 |
| 用户输入无法识别 | 提示补充"目标"或"当前状态" |
| 用户拒绝建档 | 不生成长计划，可做基础对话 |
| 追问 3 次仍缺必填 | 暂停建档，下次进入时继续 |

**空状态/加载态**：
- 首次进入：展示欢迎语 + 建档引导
- 提交中：loading 动画 + "正在为你建立档案..."
- 追问中：对话气泡式追问

### 6.3 生成规划 [P0]

**功能描述**：基于用户画像、记忆、经验库和联网搜索，生成整体方向 + 本周重点 + 今日 1-3 个低压力任务。

**业务规则**：
- 用户已有最小画像信息，或已通过追问补齐目标、阶段、可用时间
- 系统返回：整体方向、本周重点、今日 1-3 个任务
- 每个任务包含：任务名、最小启动动作（starter_action）、预计耗时、完成标准（deliverable）
- 涉及动态事实（招聘/考试/报名/政策）时必须联网核查，展示来源提示
- 所有计划经过校验节点
- 未支持场景走通用规划模式，坦诚告知"这是通用建议"

**交互流程**：
1. 用户请求生成规划（对话触发或点击"生成今日规划"）
2. 系统执行 4 节点工作流
3. 展示过渡态："正在为你规划..."（预计 10-20s）
4. 返回结果：整体方向 → 本周重点 → 今日任务卡片
5. 动态事实附带来源标签

**校验与降级**：
| 场景 | 处理 |
|---|---|
| 来源质量不足 | 只给方向性建议，标注"建议自行核实" |
| 计划校验不通过 | 回计划 Agent 重写，最多 2 次 |
| 重写仍失败 | 降级为模板计划 |
| 单节点超时 | 降级为模板计划，记录失败到 agent_steps |
| 联网失败 | 使用经验缓存/基础模板，提示"未完成实时检索" |
| 通用场景（未支持） | 告知"这是通用建议"，仍给基础规划 |

**次日续上**：
- 读取昨日完成情况 + 复盘 + 记忆摘要
- 根据状态调整今日任务数量/耗时/难度
- 连续放弃 3 天 → 主动降低任务量到 1 个/天

### 6.3.1 任务质量 5 维评分标准 [P0]

> 定义"什么算一个好的今日任务"。校验陪伴 Agent 使用此标准对计划 Agent 的候选任务逐条评估。

每个今日任务必须通过 5 维质量检查：

| 维度 | 定义 | 不合格信号（示例） | 应对 |
|---|---|---|---|
| **可启动性** | starter_action 是否具体到"打开 XX / 新建 XX / 写下 XX"级别 | "准备开始学习""了解概念""研究一下" | 触发重写，要求拆到 5 分钟内可启动 |
| **时段匹配** | 预计耗时是否匹配用户声明的当日可用时间 | 任务 4 小时，但用户今天只有 30 分钟 | 调整耗时或挪到本周重点，不进今日任务 |
| **认知负荷** | 是否避免低产出动词 | "理解 XX 概念""熟悉 XX 框架""研究 XX" | 替换为行动动词（写/读/做/填） |
| **连续性** | 是否与昨日完成/放弃/阻碍有关联或说明 | 完全无视昨天上下文，孤立任务 | 补充"接昨天的 XX，今天先..."的关联 |
| **完成可验证** | deliverable 是否是可观测的产物 | "提升认知""打好基础"这类无法判定完成的标准 | 必须是可产物化（一段文字/一个文件/一次操作） |

**校验规则**：

1. 校验陪伴 Agent 对候选任务逐一评估 5 维度，输出每维度 PASS/FAIL + 说明
2. 任一维度 FAIL → 触发回写计划 Agent，随具体维度的反馈一并送回（让重写有针对性）
3. 重写 ≤ 2 次
4. 2 次重写后仍不通过的任务**从今日清单移除**，不强制凑齐 1-3 个——**宁可只给 1 个高质量任务，也不给 3 个低质量任务**
5. 如果全部任务被移除导致今日清单为空 → 降级为模板兜底任务（基于用户画像的最基础行动，如"花 10 分钟写下你今天最想完成的一件事"），并告知用户"今天的规划遇到困难，先给你一个简单的起步"

**5 维标准的衍生设计意义**：
- 避免 LLM 生成"听起来专业但无法执行"的任务（这是 Agent 规划最常见的失败模式）
- 给校验 Agent 提供明确的、可程序化辅助判定的标准（不只靠 LLM 自觉）
- 任务质量分（5 维 PASS 数）可作为埋点指标，量化追踪 Agent 质量演进

### 6.4 今日任务卡 [P0]

**功能描述**：展示今日任务，支持开始、完成、放弃操作。

**业务规则**：
- 任务状态由后端维护，状态机见 7.3
- 点击"开始" → 状态=进行中
- 点击"完成" → 状态=已完成 + 记录完成时间
- 点击"放弃" → 必须选择/填写放弃原因 → 进入复盘引导

**异常与边界**：
| 场景 | 处理 |
|---|---|
| 任务不存在/无权限 | 提示"任务失效或无权限" |
| 状态更新失败 | 提示"保存失败，请重试"，任务状态不被错误修改 |
| 重复点击完成 | 幂等处理，不重复记录 |
| 任务已过期 | 标记为"已过期"，可重新生成 |

### 6.5 每日复盘 [P0]

**功能描述**：用户提交完成情况、情绪状态、阻碍原因和调整建议。

**业务规则**：
- 前置条件：当天存在计划或任务记录
- 用户未完成任务也可提交复盘
- 系统保存复盘记录 + 更新近期完成率、常见阻碍、任务偏好
- 必要时生成记忆候选（敏感记忆需用户确认）
- 后续计划参考复盘结果调整任务数量、耗时或难度

**异常与边界**：
| 场景 | 处理 |
|---|---|
| 复盘内容为空 | 提示补充至少一个有效字段 |
| 当天无任务记录 | 提示"今天还没有任务，先去生成规划？" |

**6.5.1 复盘影响次日计划的调整规则** [P0]

> 定义"复盘-调整-次日计划"的闭环逻辑。这是"规划陪伴"区别于"一次性规划"的核心价值。如果不做闭环，产品只是"每天重新生成一次规划的 AI 聊天工具"。

调整逻辑分两层——**规则驱动**（确定性，强制执行，优先级高）+ **Agent 驱动**（LLM 个性化判断，规则不覆盖时启用）。

**层 1：规则驱动调整（确定性）**

| 触发条件 | 调整逻辑 | 话术 |
|---|---|---|
| 连续 1 天放弃 | 任务量维持，但每个任务 starter_action 再拆细一级 | "昨天任务好像有点难启动，今天把每个任务的第一步再拆细一点" |
| 连续 2 天放弃 | 任务量减到 2 个，耗时减半 | "连续两天没完成任务，今天给你减到 2 个，慢慢来" |
| 连续 3 天放弃 | 任务量减到 1 个 + 共情话术 | "最近辛苦了，今天先做这一个就好，不做完也没关系" |
| 复盘明确声明"本周很忙/时间不够" | 整周任务耗时 × 0.5 | "收到，本周任务给你减负" |
| 复盘显示"任务方向不对/目标动摇" | 不擅自改方向，触发"重新看一下方向"引导式对话 | "你说方向可能有问题，要不我们聊一下你现在的想法？" |
| 连续完成 3 天 | 保持现状，**不擅自加量**（避免重蹈"计划过重"覆辙） | "连续 3 天稳稳完成，保持这个节奏" |

**层 2：Agent 驱动调整（LLM 个性化判断）**

当复盘记录的情况不在上表规则覆盖范围内时，由 LLM 综合以下输入做个性化调整：
- 昨日复盘的 completion / mood / blocker / adjustment
- 近 7 天的任务完成率、放弃原因分布
- 用户偏好与记忆摘要

Agent 驱动调整的**强制约束**：
1. **必须明示调整理由**——"这次我调整为 XX，因为你说 YY"
2. **不擅自改方向**——目标级调整（如"考公转实习"）必须走引导式对话，由用户确认
3. **调整幅度上限**——单日任务量调整不超过 ±2 个，耗时调整不超过 ±50%
4. **不擅自加量**——即使连续完成，也优先维持现状；加量只在用户主动要求时

**关键原则**：规则优先于 Agent——规则的调整是强制的、确定性的（避免 LLM 自由发挥导致计划忽多忽少）。Agent 只在规则不覆盖的情况下做个性化调整，且必须明示调整理由。

### 6.6 记忆管理 [P0]

**功能描述**：用户查看、确认、删除、关闭 AI 的长期记忆。

**业务规则**：
- 普通记忆（目标、偏好、学习时间、任务完成模式、稳定行为习惯）可自动写入
- 敏感记忆（情绪困扰、健康、家庭、财务、身份隐私、具体挫折经历）需用户确认后写入
- 用户可查看、删除、关闭长期记忆
- 被删除或关闭的记忆不再进入后续上下文构建
- 心理危机和高风险表达不得作为普通记忆自动写入

**异常与边界**：
| 场景 | 处理 |
|---|---|
| 删除失败 | 提示操作失败，可重试 |
| 无权限访问 | 系统不返回记忆内容 |
| 敏感记忆确认超时 | 保留在 memory_candidates 待确认池，不自动写入 |

### 6.7 安全分流 [P0]

**功能描述**：识别高风险内容，停止普通规划流程，返回安全提示。

**业务规则**：
- 高风险场景至少覆盖：心理危机、自伤自杀、医疗诊断、法律结论、金融投资建议
- 触发后停止普通规划流程，返回固定安全提示或现实求助建议
- 不生成诊断、承诺性建议或高风险操作指导
- 心理危机触发固定话术 + 心理援助热线 12356
- 后台记录安全分流事件，面向后台展示时需脱敏
- 高风险表达不得进入记忆候选

**异常与边界**：
| 场景 | 处理 |
|---|---|
| 无法判断风险等级 | 采用保守提示，停止规划 |
| 误判为高风险 | 用户可反馈"这不是我需要的"，但不恢复规划流程 |

### 6.8 后台管理 [P1]

**功能描述**：管理用户、计划、任务、来源、经验原子、Agent 运行记录。

**业务规则**：
- 查看用户列表、画像、计划、任务、复盘
- 查看 Agent 运行记录（agent_runs + agent_steps），支持按 run_id 追溯
- 敏感文本脱敏展示
- 经验原子 CRUD（后台可新增/编辑/下线经验原子）

## 7. 交互与状态规则

### 7.1 页面流转

```
前端页面结构（MVP 本地 Web 端，远期微信小程序）：
首页（今日计划页）
  ├─ 对话页（发消息、生成规划、追问）
  ├─ 今日任务卡（开始/完成/放弃）
  ├─ 复盘页（每日复盘提交）
  ├─ 记忆管理页（查看/确认/删除/关闭）
  └─ 我的（设置、隐私政策、用户协议、注销）

后台页面结构：
  ├─ 用户管理
  ├─ 计划/任务管理
  ├─ 经验原子管理
  ├─ Agent 运行记录
  └─ 安全事件记录（脱敏）
```

### 7.2 产品细节与交互规则

| 场景 | 用户看到什么 | 系统规则 | 边界情况 |
|---|---|---|---|
| 首次建档 | 目标、阶段、可用时间采集 | 只采集规划必要信息；可选字段可跳过 | 缺必填时追问 1-3 个问题 |
| 生成规划 | 整体方向、本周重点、今日 1-3 个任务 | 任务必须含最小启动动作、预计耗时、完成标准 | 动态事实缺来源时只给方向性建议 |
| 今日任务 | 任务卡片、开始/完成/放弃入口 | 任务状态由后端维护 | 放弃任务必须记录原因 |
| 每日复盘 | 完成情况、情绪、阻碍、调整建议 | 结构化记录，可生成记忆候选 | 敏感记忆需用户确认后写入 |
| 记忆管理 | AI 记住了什么、确认、删除、关闭 | 长期记忆必须可查看、可删除、可关闭 | 关闭后不再用于后续上下文 |
| 安全分流 | 停止普通规划，给出安全提示 | 高风险触发后不继续普通规划 | 后台展示敏感文本需脱敏 |
| 高风险场景 | 固定话术 + 求助热线 12356 | 走固定话术，不交给 LLM 自由生成 | 不进入记忆候选 |

### 7.3 状态机

**任务状态机**：
```
待开始 → 进行中 → 已完成
  │         │
  │         └→ 已放弃（必须记录原因）
  │
  └→ 已过期（次日未完成自动标记）
```

**计划状态机**：
```
草稿 → 已生成 → 已采纳（用户开始任一任务）→ 进行中 → 已完成（所有任务完成/放弃）
                                    │
                                    └→ 已放弃（用户主动放弃整个计划）
```

**记忆状态机**：
```
候选（待确认）→ 已确认（写入长期记忆）→ 已关闭（不再进入上下文）→ 已删除（永久删除）
                    │
                    └→ 普通记忆直接跳过候选，自动写入
```

### 7.4 异常态/空状态/加载态规则

| 场景 | 空状态 | 加载态 | 异常态 |
|---|---|---|---|
| 今日计划页 | "今天还没有计划，去生成一个？" + 按钮 | "正在为你规划..." + 动画 | 规划失败：显示错误 + "重试"按钮 |
| 任务卡 | "暂无任务" | 操作中 loading | 操作失败 toast + 状态不变 |
| 复盘页 | "今天还没有任务记录" | 提交中 loading | 提交失败 toast + 内容保留 |
| 记忆管理页 | "AI 还没有记住你的信息" | 加载中 skeleton | 加载失败 + 重试 |
| 对话页 | 欢迎语 + 引导示例问题 | "正在思考..." + 动画 | 超时提示 + "重试" |

## 9. 数据需求


## 10. 范围说明

### 10.1 MVP 范围（In Scope）

- 前端客户端（MVP 本地 Web 端）：对话页、今日计划页、任务卡片、每日复盘页、记忆管理页
- Java 后端：用户、画像、计划、任务、复盘、记忆、来源、Agent Trace 的 CRUD 和 API
- Python Agent：4 个核心 Agent + PlanState + Web Search Tool + RAG Retriever
- 首发场景：计算机央国企求职、考公入门、AI/后端实习准备
- 通用场景：未支持场景走通用规划模式
- 后台管理：Agent 运行记录查看、用户/计划/任务管理、经验原子管理

### 10.2 MVP 不做（Out of Scope）

- 变现/付费功能（先把项目完整跑通）
- 不新增超过 4 个核心 Agent 的复杂多 Agent 编排
- 不做 Agent 群聊、Swarm、开放角色广场
- 不接入 MCP 或外部自动执行工具
- 不做日历、Notion、飞书、招聘系统等外部写操作
- 不做复杂长期记忆运营系统
- 不做主动推送、主动陪伴和自动任务执行
- 不做语音、2D 形象、成就系统或社交功能

### 10.3 重新评估的时间点

- **上线后 1 个月**：根据计划采纳率/第一步完成率数据，决定是否做主动推送（模板消息提醒）
- **上线后 2 个月**：根据用户增长决定是否扩展更多垂直场景
- **上线后 3 个月**：根据成本数据决定是否做变现/付费功能

## 11. 风险与降级策略

### 11.1 产品风险

| 风险 | 等级 | 降级策略 | 责任人 |
|---|---|---|---|
| 用户信息不足 | 中 | 最多追问 1-3 个关键问题，不生成长计划 | 产品 |
| 计划质量低 | 高 | 校验节点拦截 + 最多重写 2 次 + 模板降级 | 产品 + 算法 |
| 用户不信任 AI 计划 | 高 | 来源标注 + "以官方公告为准" + 免责声明 | 产品 |
| 通用人偶模型向下覆盖 | 中 | 速度 + 经验原子沉淀防御 | 产品 |

### 11.2 技术风险

| 风险 | 等级 | 降级策略 |
|---|---|---|
| 联网失败 | 中 | 使用经验缓存/基础模板，提示"未完成实时检索" |
| 来源质量低 | 中 | 只给方向性建议，不给确定结论 |
| 计划校验不通过 | 中 | 退回计划 Agent 重写，最多 2 次，仍失败模板化输出 |
| 模型成本过高 | 中 | 意图识别/校验用小模型，计划生成和蒸馏用强模型 |
| 模型超时 | 中 | 降级模板计划，记录失败到 agent_steps |
| LangGraph 调试困难 | 中 | 接入 LangSmith 可观测性，pin 版本 |
| 双服务联调问题 | 低 | 接口契约先行，Mock 对接 |

### 11.3 合规风险

| 风险 | 等级 | 降级策略 |
|---|---|---|
| 个人主体无法上线 | 🔴 高 | 注册企业主体 + 算法备案（2-6 个月，与开发并行） |
| 敏感记忆误写入 | 高 | 敏感记忆默认进待确认池，用户确认前不进入长期上下文 |
| 心理危机/高风险 | 高 | 停止普通规划，固定话术 + 12356 热线，不交给 LLM 自由生成 |
| 内容审核不通过 | 高 | LLM 输出先审后发，不审不发 |
| 数据出境 | 中 | 使用国内大模型 API，避免出境 |
| 未成年人使用 | 中 | 注册声明年满 18，发现未成年限制敏感功能 |

### 11.4 Plan B：MVP 假设验证失败时的应对

> 在 MVP 启动前明确"如果关键假设验证失败，可能原因是什么，对应调整方向是什么"——避免 MVP 上线后被动应对。

| 指标不达标 | 可能原因 | Plan B 调整方向 |
|---|---|---|
| **每周第一步完成率 < 35%**（北极星失败） | 任务颗粒度不够小，starter_action 不够具体 | 召集 5 名用户深度访谈，观察他们做任务的卡点，迭代 Prompt；引入"30 分钟启动原则"——每个 starter_action 必须可在 30 分钟内完成 |
|  | 用户不信任 AI 计划 | 强化"我为什么这么建议"的透明度，增加来源解释；用户可手动调整后再生成 |
|  | Starter_action 在 UI 上不够突出 | 强化 starter_action 的视觉引导（一键复制 / 浏览器打开 / 计时） |
| **计划过重率 > 20%** | 任务数量虽减到 1-3 但单个时长仍太长 | 引入单任务硬上限（≤ 60 分钟），超时拆分；用户可在生成时声明今日心情（低端/正常/专注），影响任务量 |
| **复盘提交率 < 20%** | 复盘表单太繁琐 | 把复盘改成 1 问 1 答（"今天感觉怎么样？" 单选）+ 可选补充文字；或把复盘融入"完成任务"的庆祝话术里 |
| **7 日回访率 < 10%** | 用户感受不到持续价值 | 加每周"成长轨迹回顾"页（可视化已完成的任务累积）；考虑加微信订阅消息（一次授权、每日推送"今天任务准备好了"） |
| **通用场景（外圈）质量明显低于内圈** | 经验原子库覆盖不足 | 从"声称通用"退回到"诚实告知"——未支持场景明确分类标记"通用建议，专业度有限"；同时扩张经验原子库 |
| **Agent 评测通过率 < 85%** | LLM 推理能力不足 | 升级到更强模型（DeepSeek → GLM 最强 / GPT-4o 兜底），但需评估成本；或减少 Agent 自由度，增加规则约束 |
| **单 plan_run 成本 > ¥0.2** | Token 消耗超预期，或重写率过高 | 加 plan_run 频次限制（每用户每日 ≤ 3 次）；优化 Prompt 减少输入 token；缓存相似诊断结果 |
| **端到端延迟 P95 > 20s** | LLM 节点串行等待 | 拆分为两段返回：先返回诊断 + 整体方向（5s 内），后台继续生成今日任务，完成后补发 |

| 微信小程序平台（远期） | 微信 | 分发渠道 | 类目审核、合规要求 |

#### 示例 A：计算机应届想进央国企（内圈 - 经验原子加持）

**建档输入**：
- 目标：进央国企做 Java 后端
- 阶段：应届大四，离秋招还有 3 个月
- 可用时间：工作日 19:00-22:00（3h），周末全天
- 可选：专业课基础中上，没有像样项目，简历空白

**诊断 Agent 输出**：
```json
{
  "intent": "generate_plan",
  "goal_type": "job_hunting",
  "scene": "central_enterprise_backend",
  "stage": "senior_3m_before_autumn",
  "available_time": "weekday_3h_weekend_full",
  "info_gaps": ["specific_target_companies", "project_experience_level"],
  "needs_clarification": true,
  "clarify_questions": ["你瞄准的央国企是哪几家？", "你之前做过的项目是什么级别的（课设/比赛/实习）？"]
}
```

**追问补齐** → 用户回答"中国移动、工商银行科技岗；课设做了一个电商系统"。

**搜索蒸馏 Agent 输出**：
- 命中经验原子库（3 条）：
  - 原子 1："央国企秋招提前批 7-8 月就开，比互联网早"（来源：牛客面经，适用：应届大四）
  - 原子 2："工行科技岗技术面重项目深度，八股其次"（来源：经验帖）
  - 原子 3："课设电商系统需包装为可讲深度的项目——拆为高并发场景设计"（来源：面经）
- 联网核查："工商银行 2026 科技菁英计划" → 来源：工行招聘官网，可靠。

**计划 Agent 候选输出**：
- 整体方向：3 个月内完成"项目深度包装 + 八股巩固 + 简历优化 + 提前批投递"4 阶段
- 本周重点：把电商课设拆成一个可讲 30 分钟的深度项目
- 今日任务（候选 3 个）：
  1. 整理电商课设的 3 个技术难点 + 各自解决方案（2h）
  2. 背诵 JVM 内存区域 + 写下你能讲出来的版本（1h）
  3. 查工行科技菁英计划 JD,标记技术栈缺口（30min）

**校验陪伴 Agent 输出**：
- 5 维评分：任务 1 PASS / 任务 2 可启动性 FAIL（"背诵"是低产出动词）→ 触发重写
- 计划 Agent 重写任务 2：「写下 JVM 内存区域结构图 + 用 3 句话解释每块用途」（1h）
- 再评分：5 维全 PASS
- 最终话术："你大四还有 3 个月，时间够用。先把课设吃透——这是央企技术面最容易出彩的地方。今天先整理技术难点，我把它放第一位了。"

**前端展示**：整体方向 + 本周重点 + 3 个任务卡（每个含 starter_action："打开你电商课设代码库 / 新建一个 Markdown / 打开工行招聘官网"）
