# Career Planning Buddy 用户使用说明

本说明按当前界面介绍从首次进入到材料管理、求职规划、每日执行、模拟面试和报告回流的完整流程。

## 1. 登录与建档

打开应用后，可以注册账号、登录或使用访客入口。首次进入需要填写最小画像：

- 目标方向；
- 当前求职阶段；
- 每日可投入时间；
- 技能概况和截止日期等可选信息。

这些信息是后续规划的上下文，不需要在每次请求中重复填写。可以在 `/settings/profile` 更新画像，在 `/me` 查看账号与数据入口。

## 2. 从工作台开始

登录后默认进入 `/workspace`。工作台汇总当前简历、目标 JD、路线、今日任务和模拟面试状态，并根据缺失信息提示下一步。

推荐首次使用顺序：

```text
完善画像 → 添加简历和目标 JD → 确认求职目标
→ 生成路线 → 完成今日任务 → 模拟面试 → 处理报告建议
```

## 3. 管理简历和目标 JD

在 `/materials` 可以：

1. 添加简历文本并保留版本；
2. 添加目标岗位的 JD；
3. 选择简历版本和 JD 发起材料诊断；
4. 查看主张的支持度、理由和证据缺口；
5. 逐条接受或拒绝改写建议；
6. 确认后生成带父版本引用的新简历版本。

系统不会静默覆盖原始简历。诊断只基于已提供材料和可选面试证据，不会虚构项目经历、数字或技能。

## 4. 生成求职路线

进入 `/today` 发起规划，填写目标、开始日期和结束日期。系统会先生成目标摘要；信息不足时先追问，用户确认后才创建路线。

生成过程中页面通过 SSE 展示进度。完成后可以在 `/journey` 查看：

- 1–8 周的整体方向和每周重点；
- 固定 7 天执行周期，最后一个周期可以短于 7 天；
- 每天一个关键任务；
- 任务的起步动作、交付物、预计时长、检查项和来源。

规划窗口严格位于用户确认的日期范围内。

## 5. 执行今日任务

`/today` 优先展示当前最需要完成的任务。任务可以开始、更新检查项、完成或放弃；详细计划和历史版本在 `/journey` 中查看。

| 状态 | 含义 |
|---|---|
| 待开始 | 任务已创建，尚未执行 |
| 进行中 | 用户已经开始任务 |
| 已完成 | 交付物和检查项已经确认 |
| 已放弃 | 本次不再执行，可在复盘中记录阻碍 |

任务状态由服务端状态机控制，刷新页面不会丢失已经提交的进度。

## 6. 复盘与调整

在 `/reviews` 记录完成情况、阻碍、时间变化和调整请求。系统结合任务事实给出继续或调整建议。

- 继续：保留当前中期方向，生成后续行动；
- 调整：根据新的时间、目标或持续阻碍创建计划新版本。

两种操作都需要用户主动确认。旧计划只有在新版本成功创建后才归档，已完成任务不会被删除。

## 7. 开始模拟面试

在 `/interviews/new` 选择简历版本、目标 JD 和训练配置，开始一场 4–6 题的定向面试。

面试过程中：

- Session 冻结所选材料版本；
- 每道题保存题目、回答、分析和证据引用；
- 追问次数有限；
- 页面刷新或单题处理失败后可以恢复、重试或跳过；
- 文本回答始终可用；单题音频只用于转写和可靠的客观指标。

系统不保存原始音频，也不根据语音或文本推断情绪、性格或心理状态。

## 8. 阅读报告并回流训练

完成面试后，在 `/interviews/:id/report` 查看：

- 优势和薄弱点；
- 对应的原回答证据；
- 可执行的训练动作；
- 可选的任务调整或材料改写建议。

训练动作不会自动进入计划。用户预览并确认后，系统才写入执行层。在 `/growth` 可以查看训练记录和可比场次的复测结果；证据不可比时不会强行给出“提升”结论。

## 9. 管理个人记忆

复盘或报告中的稳定偏好、限制和重复阻碍可以成为记忆候选。候选只有在用户确认后才成为后续规划可检索的个人记忆。

在 `/memories` 可以查看、确认、拒绝、关闭、恢复或删除记忆。未确认、已关闭、已删除和其他用户的记忆不会进入当前用户的规划上下文。

## 10. 常见状态与处理

| 页面状态 | 建议操作 |
|---|---|
| 信息不足 | 回答目标澄清问题后重新确认 |
| 生成中 | 保持页面打开；断线后重新进入会读取已持久化事件 |
| 已取消 | 根据需要重新发起，不会生成半成品业务结果 |
| 已降级 | 阅读降级原因和保守结果，修正输入或 Provider 配置后重试 |
| 单题失败 | 保留已有文本，选择重试或跳过 |
| 建议待确认 | 先预览影响范围，再决定接受或拒绝 |

## 11. 数据与隐私

- 简历、JD、面试回答和个人记忆都属于敏感数据；
- 不要在公开 Issue、截图或日志中提交真实个人信息和凭据；
- 本地部署时应使用独立的 JWT Secret 和数据库密码；
- Provider Key 只配置在服务端 `.env` 或部署系统 Secret 中；
- 当前仓库不提供承载真实用户材料的公共托管实例。

更多信息见 [Security Policy](../../SECURITY.md) 和 [Provider 配置与部署](../third-party-integration/provider-configuration.md)。
