# Career Planning Buddy 产品概览

Career Planning Buddy 是面向计算机专业学生的证据化 AI 求职教练。它把简历、目标岗位、求职规划、每日执行和模拟面试放进同一个可追踪闭环，帮助用户从“知道该准备什么”走到“今天完成什么、完成后如何调整”。

当前产品事实以 [Current System Overview](../architecture/current-system-overview.md)、数据库迁移和代码为准。

## 用户问题

- 简历、目标 JD、项目准备和面试训练彼此割裂；
- 通用建议缺少优先级、时间边界和可验证交付物；
- 执行中断后，后续计划没有利用完成、放弃和阻碍事实；
- 面试反馈停留在一份报告里，不能进入训练任务或材料改进；
- 模型输出难以复现、追踪和回归验证。

## 核心闭环

```text
账号与画像
  → 简历版本 + 目标 JD
  → 目标确认 + 求职路线 + 今日任务
  → 执行进度 + 每日复盘 + 版本化调整
  → 定向模拟面试 + 证据化报告
  → 训练动作 / 个人记忆 / 简历新版本
  → 复测与跨场次比较
```

## 当前功能

| 模块 | 用户价值 | 关键约束 |
|---|---|---|
| 求职工作台 | 汇总当前材料、路线、任务和面试状态，给出下一步建议 | 建议来自已持久化的当前状态 |
| 求职材料 | 管理简历版本和目标 JD，进行主张证据诊断与定向改写 | 改写逐条确认，只创建新版本，不覆盖原文 |
| 路线与今日行动 | 将目标转成 1–8 周方向和固定 7 天执行周期 | 目标先确认；任务带起步动作、交付物、预算和检查项 |
| 任务与复盘 | 记录开始、完成、放弃、实际阻碍并继续或调整计划 | 重规划保留已完成事实并创建计划新版本 |
| 模拟面试 | 基于冻结的简历和 JD 进行 4–6 题定向训练 | 逐题短 Run、有限追问、失败可恢复 |
| 面试报告 | 用原回答证据总结优势、薄弱点和训练建议 | 高影响训练动作需要用户确认 |
| 成长与复测 | 汇总训练记录，并比较证据可比的面试场次 | 不把单次表现解释为稳定能力结论 |
| 个人记忆 | 保存用户确认的长期偏好、限制和重复阻碍 | 候选先确认、按用户隔离、可关闭或删除 |
| 开发者工具 | 查看 Run、Step、Tool、Event、Snapshot 和离线评测 | 服务端 `dev` 角色校验是访问边界 |

## 产品原则

### 证据优先

材料诊断和面试报告尽量引用简历主张、JD 要求或用户原回答。没有足够证据时明确标记不足，不补写用户没有提供的经历或结果。

### 行动优先

路线可以覆盖中期方向，执行层只展开近期任务。任务必须有明确起步动作、可观察交付物和时间预算，避免用“学习一下”“熟悉一下”充当行动。

### 人工确认

简历改写、训练任务、计划调整和长期记忆都经过用户确认。Agent 生成候选，Service 和状态机负责最终写入与版本变化。

### 可恢复、可追踪

Agent Run 的事件、步骤、快照和最终结果持久化到 PostgreSQL。SSE 断线后可以从已提交事件继续读取；每个 Run 恰好一个终态事件。

### 明确边界

系统不自动投递简历，不代替招聘决策，不执行背景调查，不根据音频或文本推断心理状态，也不把离线指标描述为真实用户效果。

## 产品页面

| 路径 | 页面 |
|---|---|
| `/workspace` | 求职工作台 |
| `/materials` | 简历与目标 JD |
| `/today` | 今日行动 |
| `/journey` | 求职路线与计划版本 |
| `/reviews` | 每日复盘 |
| `/interviews` | 模拟面试列表 |
| `/interviews/new` | 面试配置 |
| `/interviews/:id` | 面试房间 |
| `/interviews/:id/report` | 面试报告 |
| `/growth` | 成长与复测 |
| `/memories` | 个人记忆管理 |
| `/dev/runs`、`/dev/evals` | 开发者追踪与评测 |
