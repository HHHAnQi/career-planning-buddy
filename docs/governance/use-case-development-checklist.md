# 新增用例开发检查表

## 业务

- [ ] 用户是谁、解决什么问题？
- [ ] 输入、输出和非目标是否明确？
- [ ] 是否需要追问缺失槽位？
- [ ] 是否改变计划、任务或记忆状态？

## 契约与数据

- [ ] API spec 已更新；
- [ ] Pydantic DTO 与 OpenAPI 一致；
- [ ] 表字段、索引、约束和迁移已定义；
- [ ] 用户隔离条件由服务端可信身份注入；
- [ ] 幂等键、乐观锁或事务边界已说明。

## Agent

- [ ] 确定性逻辑优先使用规则节点；
- [ ] LLM 输出有 Schema；
- [ ] Tool 只读/白名单，具有参数与结果 Schema、超时、结果上限、用户隔离和 fixture；
- [ ] LLM/Tool 次数、Token 和总截止时间有统一预算；
- [ ] Graph State 可序列化，input/config snapshot 明确；
- [ ] completed/degraded 的 result_kind 和唯一 terminal event 明确；
- [ ] 降级结果明确标注，不伪装为正常成功。

## 安全

- [ ] Prompt 注入和不可信网页内容不覆盖系统规则；
- [ ] 敏感信息不进入日志、Trace 和长期记忆；
- [ ] 高风险请求进入 `safe_response`，资源信息从配置读取并按地区维护；
- [ ] 不提供医疗诊断或替代专业服务。

## 验证

- [ ] 正常路径测试；
- [ ] 权限与越权测试；
- [ ] 超时、取消、Provider 失败测试；
- [ ] 状态机非法转移测试；
- [ ] 至少一个 Eval Case；
- [ ] 文档和验收命令已更新。
