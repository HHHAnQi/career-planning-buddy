# 规划质量 Rubric（v1）——人工标注与 Judge 校准共用标准

> 本文档是唯一的评分标准：人工标注员按它打分，LLM Judge 的 prompt 由它生成，
> 校准（`scripts/calibrate_rubric_judge.py`）比较两者的一致率。
> **标注员与 Judge 必须用同一把尺子**——修改本文档意味着 judge prompt 版本升级与重新校准。

## 评分对象

一次规划 Run 产出的 `PlanCandidate`（含 summary、rationale、weekly_focus、7 天任务列表），
及其对应的请求上下文（用户输入、画像、时间预算、证据目录）。

## 四个维度（每维 1–5 分，整数）

### D1 目标对齐（goal_alignment）

规划是否回应了用户的真实请求与画像（方向、阶段、技能水平、时间预算）。

| 分 | 判据 |
|---|---|
| 5 | 直接回应请求；任务与画像的 goal_type/stage/技能水平精确匹配；时间预算被尊重 |
| 3 | 大体相关但有明显偏差：方向正确但阶段错位（如对 exploring 用户安排 applying 密度）、或忽略明确的时间约束 |
| 1 | 答非所问；任务与画像方向无关；或把用户没提的目标强加进来 |
| 2/4 | 相邻档位之间：主体符合档位描述但含一处次要违例 |

补充判据（2026-08-25 校准迭代，源自标注仲裁）：

- **预算利用率**：尊重时间预算 ≠ 只不超限——任务时长应接近声明预算
  （单日合计 ≥ 声明值的 80%）。预算 75 分钟而任务只安排 45 分钟属于
  "用不满"，按 3 分处理（能力未匹配承诺）。
- **流程完整性**：任务序列不得跳过该目标的必要环节。例如目标是完成一个
  开发项目，序列却从环境搭建直接跳到前后端联调（缺失开发环节）——关键
  环节缺失按 3 分以下处理。

### D2 证据支撑（evidence_grounding）

主张与任务是否有证据目录中的来源支撑；是否有无中生有的断言。

| 分 | 判据 |
|---|---|
| 5 | 所有关键主张（优势判断、差距判断、行动理由）都有可见证据；evidence_refs 全部真实存在 |
| 3 | 多数主张有支撑，但 1 处关键判断无证据或引用了不在目录中的来源 |
| 1 | 大部分主张无证据；或出现虚构的来源/数据/公司要求 |
| 2/4 | 同上插值 |

注：引用了**目录中不存在的证据 id** 是硬错误，本维直接 1 分（与运行时证据可见性校验器同一标准）。

### D3 可执行性（executability）

用户拿到任务后能否直接开始做：步骤具体、交付物可验证、单日工作量合理。

| 分 | 判据 |
|---|---|
| 5 | 每个任务 2–3 个有序步骤且都具体到可操作（"做 X 并产出 Y"）；交付物可检验；单日时长贴合预算 |
| 3 | 任务可做但含糊（"学习相关知识"类占位 ≥2 处）；或单日工作量超预算 50% 以上；或缺少可验证交付物 |
| 1 | 任务空洞（多数是愿望式表述）；步骤顺序逻辑错误；工作量严重超载 |
| 2/4 | 同上插值 |

**反注水条款**：冗长但无信息增量的列表（为显得完整而堆砌条目）不得加分，反而按 3 分以下处理。

**场景真实性条款**（2026-08-25 校准迭代）：任务内容必须符合目标用户的
真实场景。本项目用户是中国求职者：沟通投递以招聘平台（Boss 直聘等）
为主，出现纸质时代式的"撰写求职信"类设计即脱离场景，按 3 分以下处理；
任务量也要与目标周期匹配（如"探索岗位需求"一天只查 3 家公司，覆盖面
不足以支撑决策）。

### D4 周期合规（horizon_compliance）

7 天任务与 weekly_focus 的对齐、日期连续性、周序不超前。

| 分 | 判据 |
|---|---|
| 5 | 7 个任务日期连续无缺；每个任务的 week_index 与该周的 focus/success_signal 直接对应；无超前安排 |
| 3 | 日期连续但 1–2 个任务与当周 focus 脱节；或 week_index 计算错误 |
| 1 | 日期缺失/重复；多个任务做的是后续周的工作；周对齐完全混乱 |
| 2/4 | 同上插值 |

## 标注协议

1. **单专家 + 书面理由**：一位标注员逐条打分，每维必须写 ≥15 字理由（研究结论：单专家 + 书面理由优于委员会，避免标准漂移）。
2. **盲评**：标注时不可见系统来源（mock/真实模型）、不可见其他人的分数。
3. **先锚定再标注**：标注会话开始前先读本文档全部判据；前 3 条标注后回来对照判据自查一遍。
4. **二值分带用于校准**：总分带 = good（该维 ≥4）/ bad（≤3）。Cohen's kappa 按分带计算（五级直接 kappa 会被稀疏矩阵淹没）。
5. **不一致即信号**：与 judge 不一致的条目不是"谁错"的问题，而是暴露判据歧义——回到本文档补判据，然后重新校准。
6. **文件格式**：标注写入 `evals/annotations/rubric-v1-worksheet.jsonl`（由
   `scripts/build_rubric_annotation_set.py` 生成），每行在 `annotations` 字段填
   `goal_alignment / evidence_grounding / executability / horizon_compliance`（1–5 整数）
   与 `rationale`（字符串）。带 `annotations` 的文件即为 golden set，**纳入版本库**。

## 校准门槛（业界常见值，非统一标准）

| 指标 | 门槛 | 含义 |
|---|---|---|
| Cohen's kappa（分带） | ≥ 0.6 | judge 与人工的可信下限 |
| Spearman ρ（1–5 原始分） | ≥ 0.75 | 排序一致性 |
| 分带一致率 | ≥ 80% | 约等于人与人之间的一致水平 |

三项全过 → judge 分数可进正式报告；任一不过 → 维持 `diagnostic_only`。
**Judge 与人工一致性 < 0.7 时，先修订本 rubric 再谈模型**（此时瓶颈是标准不是模型）。

## Judge 使用约束（写进 prompt 的硬规则）

- Judge 必须逐维度输出 1–5 整数分 + 简短理由，禁止"都很好"式和稀泥。
- 位置与长度无关性：不以输出长度论质量（反注水条款对 judge 同样生效）。
- 只依据输入中的请求、画像与证据目录评分，不引入外部知识。
- Judge 模型必须与被测模型**不同家族**（self-preference 实证效应 5–15%）。
