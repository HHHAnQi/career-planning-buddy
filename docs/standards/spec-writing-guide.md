# Spec 编写指南

Spec 的目标是让人和编码助手对输入、输出、状态和失败方式形成同一理解，而不是堆背景描述。

## API Spec 必填项

1. 方法与路径；
2. 身份和权限；
3. 请求 Schema 与示例；
4. 响应 Schema 与示例；
5. 幂等、事务、状态转移；
6. 错误码；
7. 测试要点。

## 数据表 Spec 必填项

字段、类型、NULL、默认值、外键、唯一约束、索引、状态枚举、删除策略和写入责任方。跨表不变量必须写明由数据库还是 Service 保证。

## Agent 节点 Spec 必填项

1. 责任与非责任；
2. 输入状态；
3. 输出状态；
4. 前置条件与不变量；
5. LLM/Tool 依赖；
6. 预算和超时；
7. 失败、降级和下一节点；
8. Trace 字段；
9. 单元与纵切测试。

## 状态机 Spec 必填项

列出全部状态、合法转移、触发者、事务副作用和非法转移的错误码。时间字段不能冒充状态，例如 `adopted_at` 不是 PlanStatus。

## 写作规则

- 使用仓库真实路径和真实枚举；
- 示例 UUID、日期和数据必须合法；
- 尚未实现的内容写“计划”，不能写“已支持”；
- 不复制同一契约到多个文档；
- 外部服务只写能力契约，不把易变化的价格和型号当永久事实；
- 每个 spec 都应能直接映射到代码和测试。
