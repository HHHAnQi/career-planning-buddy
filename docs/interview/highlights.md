# CareerBuddy 项目核心亮点（升级版总结）

> 面试开场 3 分钟版本 + 简历可直接引用的量化句式。
> 定位：用「确定性工程骨架 × LLM 智能决策」双架构，把一个 Demo 级对话应用做成 5 项 SLO 全绿、贡献可归因的生产级单 Agent 系统。

---

## 一、开场 3 分钟讲法（背这段）

「我做了一个人工智能职业规划 Agent。它不是后端套 LLM——是一个双架构系统：模型负责意图理解、任务拆解、工具决策和自我修复，代码负责 21 项规则校验、预算硬限、断点恢复和降级兜底，两边闭环。

架构上是 LangGraph 的 11 节点状态机：3 处条件分支、1 条有界修复回边、节点级 checkpoint 崩溃恢复、图内并行工具调用。规划输出必须过校验闸：已知的高频违规由确定性代码修复，未知违规交给模型智能适配，修不动就降级保底——任何情况下用户拿到的都是 schema 合法的可用计划，非法输出上不了线。

工程上最有含金量的是评测体系：30 case × 3 trial 的真实模型实验，硬门禁从 72% 做到 92%，P95 延迟 45 秒，单次成本 1 分钱以内；而且我把通过率做了双维度归因——每个 run 记录产出路径，模型贡献和工程贡献分开量化，不偷换概念。检索侧做了 pgvector 加关键词的混合检索加 rerank，Recall@5 做到 1.0。

所有待演进的能力都有量化阈值：单 Agent 什么时候拆多 Agent、Shared 记忆什么时候启用、哪些模块什么时候扩容——由先行指标触发，不靠感觉。」

## 二、八大了不起的细节（每个都是加分项）

### 1. 数据驱动的架构决策（不是拍脑袋）
- 工具预执行：因为 live 数据显示 GLM 自主触发率只有 11% → 确定性预执行接管高频路径，模型保留其余场景的工具自主权；
- 确定性修复只做 4 条规则：因为 live 数据显示这 4 类覆盖全部观测违规、且 GLM 自修复成功率 0/6；
- 禁用 GLM 隐藏思考：因为 JSON 模式下思考烧掉输出预算导致空响应，且 P50 26s→22s。
**每个"绕过模型"的决策都有一份实验报告背书。**

### 2. 三层修复漏斗（稳定性核心）
确定性修复（0 token、微秒级）→ LLM 智能修复（覆盖长尾）→ 降级模板（保底可用）。未知违规码自动进 Prometheus 计数器和结构化日志，离线迭代成新规则——规则库随 badcase 生长。

### 3. 双维度归因评测（行业稀缺的严谨度）
plan_provenance 五标签（model_pass / format_repair / deterministic_repair / llm_repair / fallback）逐 run 落库，归因脚本一条命令拆出「模型能力占比 vs 工程兜底占比」。面试被问"你的 92% 是模型还是代码"时直接现场跑。

### 4. 混合检索的完整 trade-off 记录
pgvector 余弦 + pg_trgm 关键词、RRF 融合、GPU rerank、"宽检索窄重排"（召回 50 重排 20）、相对可答性门控（top ≥ 5× 中位数）。踩过的坑都有结论：改写查询污染 reranker 输入→原始查询进 rerank；rerank 在改写查询上退化→文档化为适用边界而非硬伤。负例门控准确率、MRR、Wilson 置信区间齐全。

### 5. 上下文三级压缩（不是截断）
相关性召回（高相关老任务提升回保留区，对抗 recency bias）→ 动态 token 预算（超预算阶梯收缩到地板）→ 摘要式折叠（完成项/阻碍/调整模式结构化聚合）。全程确定性 0 LLM 调用，每次压缩留观测日志。

### 6. 生产级运行时骨架
SSE 断线恢复（Last-Event-ID + DB 原子事件序号）、崩溃恢复（lease/heartbeat/attempt fencing + checkpoint 输入指纹，恢复不重复烧钱）、BudgetGuard 四重硬限（调用数/token/deadline/取消令牌）、固定窗口限流、Prometheus 指标、三级 trace 关联、RAG 文档入库前注入防御。

### 7. 评测体系自洽性
六域确定性 grader（无 LLM 评 LLM 循环）、rubric judge v9 + 双人标注校准（kappa 0.679 过门；D3/D4 偏低定位为 rubric 歧义而非 judge 失准——知道评测的瓶颈在哪本身是能力）、mock-scripted case 自动剔除出 live 集、规模实验因语料同质化主动撤回结论（不硬编故事）。

### 8. 演进预埋而非过度设计
L3 Shared 记忆、多 Agent、分布式状态、Redis 限流——全部有量化触发阈值和届时方案；lease 是 DB 级的所以换分布式锁零语义变化；metrics 模块契约声明了换 prometheus-client 零调用点修改。**「现在不建」和「不会建」的区别就是初级和资深的区别。**

## 三、简历可直接引用的量化句式

- 设计并实现 LangGraph 11 节点单 Agent 规划系统（条件路由/有界修复环/checkpoint 恢复/并行工具调用），硬门禁通过率 72.2%→92.2%（SLO ≥85%），P95 延迟 45.5s，单次成本 ≤¥0.01；
- 构建「确定性工程兜底 + LLM 智能决策」双架构：21 项规则校验闸 + 三层修复漏斗（确定性修复/LLM 自修复/降级保底），非法输出 0 上线；
- 落地双维度归因评测体系：逐 run 记录产出路径标签，模型能力贡献与工程兜底贡献同源拆分，30 case × 3 trial 真实模型实验全程可复算（实测：通过路径模型一次通过 83.3%、确定性修复救援 16.7%）；
- 实现混合检索管线（pgvector + pg_trgm + RRF + GPU rerank + 相对可答性门控），Recall@5 = 1.0、MRR = 0.933（20 case 硬化集含负例与改写查询）；
- 设计三级上下文压缩（相关性召回/动态 token 预算/摘要折叠），确定性 0 token 完成上下文工程；
- 建立双人标注 rubric 校准流程（Cohen's kappa 0.679），并以未知规则 backlog 机制驱动规则库随 badcase 迭代。

## 四、一句话防翻车总纲

被任何问题问住时的回到主轴：**「我所有的设计决策都有三个属性：有对比取舍、有量化数据、有边界承认。」**
这个项目最值钱的不是 92.2%，是每一步从 72% 到 92% 之间的"为什么"都能讲二十分钟。
